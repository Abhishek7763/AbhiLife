# AbhiLife Data Contract v1

This document locks the first portable data contract for AbhiLife.

## Ownership rule

The application code and the user's personal data are separate systems.

- GitHub contains application source only.
- Vercel is a web preview/deployment target only.
- Personal data belongs in a user-selected Android document tree named `AbhiLife`.
- The web preview must never become the master personal-data store.

## Android storage model

The Android app will use the Storage Access Framework (SAF) and `ACTION_OPEN_DOCUMENT_TREE` through a small native Capacitor plugin.

Why SAF:

- the user explicitly chooses the folder;
- Android grants narrow access to that folder tree instead of broad file access;
- the app can take a persistable URI permission for reuse after restart;
- user-owned documents can survive application uninstall;
- an existing AbhiLife folder can be reconnected on a later install.

The app must not depend on `Android/data`, `Android/obb`, broad all-files access, or browser persistence.


## Data rules

1. Every persisted JSON document carries `schemaVersion`.
2. `manifest.json` identifies the vault and data format.
3. Current collections use a wrapper with `collection`, `updatedAt`, and `items`.
4. Daily history is split into one record per date to limit corruption scope and make recovery portable.
5. IDs are stable opaque values; display names may change without breaking relationships.
6. Paths are generated by trusted path helpers and may not contain traversal segments.
7. Writes performed by the native adapter must be atomic-style: write temporary data, validate, retain recovery state, then replace.
8. Initialization must refuse to overwrite an existing AbhiLife vault.
9. Future schema changes require explicit migrations; old data is never silently discarded.
10. `.abhilife` archive export is a portability/backup layer over this folder, not the live database.

## Native plugin contract

The JavaScript layer expects an Android Capacitor plugin named `AbhiLifeStorage` with these operations:

- `chooseRoot()`
- `getRootStatus()`
- `releaseRoot()`
- `ensureDirectory({ path })`
- `exists({ path })`
- `readText({ path })`
- `writeTextAtomic({ path, data })`
- `list({ path })`
- `deletePath({ path })`

The native plugin implementation is Phase 3.

## Current schema

`schemaVersion: 1`

The initial schema defines portable factories for:

- vault manifest
- settings
- departments
- inbox thoughts
- goals
- tasks
- habits / undesired habits
- daily records
- reviews
- notes

Validation happens before data is accepted as healthy.
